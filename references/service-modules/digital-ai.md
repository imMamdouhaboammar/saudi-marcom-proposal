# Digital and AI Module

## Owns

- websites, portals, apps, and digital experiences
- workflow automation
- chatbots and AI assistants
- content/knowledge systems
- CRM or API integrations when in scope
- AI evaluation and acceptance design
- analytics/data interfaces
- digital support and maintenance

## Discovery questions

- What user problem and workflow are being changed?
- What systems and APIs already exist?
- What data categories are processed?
- Who is controller/processor for personal data?
- Where is data hosted and can it leave Saudi Arabia?
- Which AI/model provider is intended?
- What outputs are high-risk or human-approved?
- What identity/access model exists?
- What availability/support SLA is required?
- What integrations, licenses, environments, and security reviews are required?
- Who owns source code, prompts, configurations, and generated assets at handover?

## Solution architecture

Separate:
1. discovery and requirements
2. UX/content design
3. data/integration architecture
4. implementation
5. security/privacy controls
6. AI behavior/evaluation if applicable
7. testing/acceptance
8. deployment
9. operations/support
10. handover and exit

Do not sell "AI" as a feature without a measurable job.

## AI acceptance

Define:
- supported use cases
- prohibited/high-risk outputs
- knowledge/data boundary
- grounding source
- evaluation set
- factuality/retrieval tests
- safety/privacy tests
- latency/availability targets
- human escalation
- logging and feedback
- change/version policy

## Deliverable units

- discovery sprint
- user journey/specification
- page/screen
- integration
- API connector
- workflow
- knowledge source
- evaluation cycle
- deployed environment
- license/month
- support month
- training session
- dashboard
- change request

## Data and PDPL gate

When personal data is involved:
- map data flow
- classify data
- identify controller/processor
- define purpose and access
- define retention/deletion
- identify cross-border transfers
- live-check relevant SDAIA/DGP requirements
- price controls/infrastructure that follow

Do not claim compliance because a vendor says its service is compliant.

## Commercial drivers

- integration count/complexity
- data cleanup
- environments
- licenses and model usage
- security testing
- localization
- support coverage
- hosting
- evaluation volume
- change governance

## Failure modes

- AI assistant with no evaluation contract
- personal data flow unspecified
- foreign model processing ignored
- recurring model/API cost omitted
- proof-of-concept scope presented as production-ready
- support SLA with no staffing
- data migration treated as trivial
- source-code/IP handover not priced
