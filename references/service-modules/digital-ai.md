# Digital and AI Services Module

## Activate for

Websites, portals, apps, dashboards, chatbots, AI assistants, automation, data products, integrations, CRM, digital experience, generative AI, and managed digital services.

## Architecture discovery

Resolve:
- user groups and journeys
- functional requirements
- non-functional requirements
- data sources and ownership
- personal/confidential data
- identity and access
- integrations
- hosting/data location
- model/API/vendor dependencies
- traffic and availability
- accessibility
- cybersecurity
- analytics/observability
- support model
- source-code/IP handover

For government digital services, activate the DGA branch. For cyber-sensitive scope, activate NCA and buyer-security checks.

## Workstreams

1. discovery and service design
2. UX/content architecture
3. application/frontend/backend
4. integrations
5. data/analytics
6. AI behavior layer
7. security/privacy
8. testing and acceptance
9. deployment
10. managed support and enhancement

## AI behavior contract

Define:
- approved knowledge sources
- retrieval/update method
- answer boundaries
- unsupported-answer behavior
- escalation
- human override
- prompt/instruction governance
- PII handling
- logging
- retention
- model/provider
- latency target
- safety rules where relevant
- evaluation set
- failure thresholds

Do not sell "AI accuracy" as one percentage without a defined eval.

## Deliverable units

| Deliverable | Unit | Acceptance examples |
| --- | --- | --- |
| discovery | workshop/sprint | approved journeys and requirements |
| UX/UI | page/flow | approved responsive flow and accessibility checks |
| website/portal | release | functional acceptance tests pass |
| integration | integration | authenticated test, error handling, documentation |
| dashboard | dashboard | defined metrics, refresh logic, access controls |
| AI assistant | release/model config | eval suite, grounding, escalation, privacy behavior |
| automation | workflow | trigger/action/error/retry evidence |
| security test | assessment | agreed scope and remediation record |
| support | month | SLA, channels, hours, severity model |

## Saudi-specific checks

When applicable:
- PDPL and cross-border transfer
- DGA regulatory framework for government digital work
- DGA accessibility requirements
- NCA Essential Cybersecurity Controls
- NCA AI cybersecurity guidance status
- buyer architecture/security policies
- hosting and cloud requirements

Draft/public-consultation guidance must not be represented as binding final regulation without fresh status verification.

## Pricing drivers

Separate:
- discovery
- design
- implementation
- integration
- data migration/preparation
- security
- licenses
- cloud/hosting
- model/API consumption
- support
- content/knowledge preparation
- enhancement backlog

Consumption-based services need assumptions and a mechanism for overage.

## Failure modes

Block or revise when:
- personal data flows are unknown
- "on-prem" or "Saudi hosting" is assumed without source
- API/model consumption is unlimited in a fixed price
- acceptance criteria are only visual
- AI has no eval set or unsupported-answer behavior
- accessibility is promised without test method
- security controls are copied without applicability
